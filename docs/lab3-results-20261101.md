# BenchLevel ЛР3: виміряна версія та обмеження

Програма для Nucleo-C031C6 працює як один bare-metal super loop. Середовище експериментів: Ubuntu 24.04, Docker, STM32 HAL, Wokwi. Кодова база для вимірювань — кандидат source ID `156cce9152e16852`, ELF SHA-256 `9bd2a08470af183e18386b2763c994dad2050f76f84c59adb1e84287c1f48b09`, HEX `d47d19bbe81e8310e7f0b7032d6cdd81ba376f799623797bbb11e87037aee115`.

## Докази та вимірювання

S1 охопив 185 000 мс MCU. S2 охопив безперервні 3 610 000 мс MCU; незалежний ADC-маркер D0 у межах цього проміжку має 72 201 фронт за 3609,925 с VCD. У 7581 телеметричному рядку інтервалу LEVEL та errors=0. При цьому `loop_skip=79927`, `command_late=13`; CPU load і короткі WCET недоступні при роздільності годинника 1 мс. SAMPLE 45/50/55 мс min/avg/max, n=72 260; stack watermark 668 B, heap 0. Тривалість обох попередніх перерваних S2 до цього інтервалу не додавалася.

S3 — дві окремі передачі STATS, по 25 підтверджених STATUS усередині кожної. D6, усі перемикання D4 та UART EVT пов'язані за порядком FIFO. Перша група: 212,600/433,035/650,501 мс min/avg/max; друга, зі зсувом подачі на 20 мс host-часу: 100,758/313,721/527,514 мс. Значення не усереднено між групами. Це результат 50 пар, а не доказ 20-мс реакції під STATS; PRD формулює 20 мс поза монопольним експортом STATS і flash.

Окремий адресний PROBE дав 0xD2 NACK, потім 0xD0 ACK; UART показав ERROR/NACK і повернення до id=68, UNCAL. Це симуляція адресної відмови, не фізичне від'єднання і не повторне калібрування. SAVE дав ACK, але після erase перше перевірене слово не відповідало очікуваному all-FF: `checked=1`, `bad=2048` є зсувом, а не кількістю байтів. Причина не встановлена; довговічне flash-збереження і фізичне знеструмлення не підтверджені.

Сирі UART, конфігурації, VCD та аналіз зберігаються поза репозиторієм власника у `Lab03/Work/candidate-uart-arm-20261030/evidence/`. S2 UART SHA `79dc76d50ef2ececea51d357b707b64744993f0c60047055cfa51636196c7472`, VCD SHA `29abc7af6a317654dd635d0d41a8ad8623f60f57fabb908a64681fa9f146e3ce`; S3 `suite-S3-stats-20261031` і `suite-S3-aligned-20261101` містять `physical-decode.json`, `pair-analysis.json`, UART та VCD; PROBE — `probe-recovery-20261101`.

## Відтворення виміряної збірки

Збережений ідентифікатор `firmware/Platform/build_id.h` генерується і не входить до Git. Для побітового відтворення архівного кандидата потрібний заголовок з `BENCH_GIT_ID` `76ba62a2b1e5-candidate` та `BENCH_SOURCE_ID` `156cce9152e16852`, після чого `make -C firmware BUILD_DIR=build-verify -o Platform/build_id.h` у локальному Docker-образі. Саме так із ізольованого дерева підтверджено ідентичність ELF та HEX до виміряних. Звичайна збірка генерує актуальний source/git ID, а отже її хеш не слід ототожнювати з архівним без окремої перевірки.

ARM build: FLASH 27 652 / 28 672 B, RAM 7 824 / 12 288 B, CALIBRATION 0 / 4096 B; text 27 544 B, data 108 B, bss 7720 B. Це linker-облік, не розподіл фактично використаного стека. Для готовності потрібні повна таблиця FR, межа UART/частоти, запуск/готовність сенсора, перевірка на фізичній платі та поточний звіт; відсутні результати не слід оголошувати успішними.
